# 运行约束与异常处理（0.2.9.5）

本文件回应“检测规避”的要求：新版通过控制访问频率、等待页面状态和失败时停止，减少异常请求。网站如何检测自动化由其服务端和页面规则决定，**任何固定间隔都不能保证不会被判异常**。没有加入伪造 User-Agent、修改指纹、隐藏自动化标记、生成仿人鼠标轨迹或破解验证码的功能。

## 已实现的稳定性措施

| 措施 | 实际行为 | 适用范围 |
| --- | --- | --- |
| 自动请求节奏 | 默认最小间隔 5 秒，可设 2–120 秒；图片逐张加载，搜索和模型使用同一节奏；等待可被暂停／页面退出打断 | 新增站点的自动题目流程；不修改站点自己发送的正常请求 |
| 防止并发堆积 | 单页面一个控制器和调度器，同一流程不并行处理多道题；每秒检查页面状态属于本地 DOM 检查，不是每秒请求服务器 | 当前页面；不同标签页没有跨页协调 |
| 模型失败冷却 | HTTP 429、5xx、网络请求失败或超时后，连续失败按 15、30、60、120、240、300 秒冷却；有效的 `Retry-After` 秒数或日期若更长，则遵守更长时间 | 自动模型和搜索调用；不是自动重发机制 |
| 明确停止点 | 失败题停下等待；冷却中禁用手动重试，冷却后也需手动点“重试当前题”；401、403、配置错误保留人工修复入口 | 不变更账户、权限或 API Key |
| 操作等待 | 默认填选后等 3 秒，并核对真实选中状态再提交；切课至少等 2 秒且以正常课程完成回执为前提 | 新增站点的提交与切换；不是模仿人工以隐藏脚本 |
| 验证接管 | 发现已适配的验证码／人机／登录验证节点后中止当前查询，后续点击前重新核对；由用户手动完成验证 | 不识别／解决验证码；未知的新验证页面可能需要用户主动暂停 |
| 回执保护 | 保留已提交状态，等待成功／失败回执；超过 15 秒提示未确认，不自动补发 | 课程弹题、课程完成和试卷提交 |
| 生命周期恢复 | 缓存页面恢复后只运行一个调度器；暂停／退出中断未完成查询，迟到答案不再填入 | 同一页面会话，刷新会清除文字题缓存 |

`Retry-After` 用法参考：[MDN HTTP Retry-After](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Retry-After)。实现支持秒数和 HTTP 日期；本地测试覆盖两种格式。

题目图片最多 6 张，每张不超过 5 MB，支持 PNG、JPEG、GIF、WebP；图片读取超时为 20 秒。图片载入失败会停在当前题，不无限重试。模型请求的超时沿用原配置，实际范围 10–300 秒。手动“获取模型”“测试连接”、脚本启动的原有通知／依赖资源，以及网站自身的请求不纳入新增自动请求限速器；请勿连续点击测试按钮。

## 运行时应遵守的约束

1. 同一课程、同一试卷只保留一个自动运行标签页，勿同时启用多个同类助手。限速器属于当前页面，不能为多个页面合并限速。
2. 保持网络和登录有效；休眠、后台标签节流、浏览器自动播放策略和网站更新都会影响实时性。建议把当前课程放在前台，需要离开时点“暂停”。
3. 不要把最小请求间隔当成网站许可的速率。若平台限制更严格，请增大间隔或停止自动流程；遇到访问拒绝或登录验证时人工处理。
4. 倍速只使用播放器支持的控制方式；不修改时长、拖拽进度、不伪造心跳或成绩。倍速是否计入进度由网站决定。
5. 不自动开始一场试卷，不替用户签名，不绕开正式试卷的倒计时、离开页面检测或访问控制。使用正式流程前，应自行检查该流程允许的工具与提交设置。
6. 模型可能给错答案。不能将“已查询”“已填选”或“网站已接受提交”解释为答对或课程已记满；以网站结果为准。

## 验证结论的范围

本版 109 项自动检查通过，包含原有 95 项及新增 14 项；验证使用隔离的 Edge、网站已发布的页面组件和模拟的后台／模型响应。还检查了真实解码视频的播放倍速。

这不等于验证了真实账户的课程进度、模型费用、试卷成绩或网站所有检测逻辑。已登录 Edge 的桌面连接当前返回 native pipe unavailable，实际安装确认及带登录状态的实站流程尚不能由这些检查证明。安装尝试的最终状态见 `安装状态-0.2.9.5.md`。
