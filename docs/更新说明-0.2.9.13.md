# 0.2.9.13：修复切下一视频触发返回首页

## 原因与证据

用户反馈切换到下一视频时返回首页。本次重新读取官方公开学习组件，找到与现象对应的触发路径：播放器 `#container` 注册捕获阶段的点击监听，检查事件的 `isTrusted`；脚本生成的点击会进入异常处理，暂停播放器，并在约 3 秒后跳转智慧树首页。目录切换处理也检查不可信的 `PointerEvent`。

旧版学习控制器在视频自然结束且收到成功保存回执后调用 `next.click()`。浏览器生成的该事件不是真实用户点击，因此这条路径会触发网站检查。本次加入相同事件检查的隔离回归，旧版在 38 个场景中通过 37 个，新增场景因脚本切课点击失败。该证据证明代码存在可复现的触发路径，尚不能代替用户账号的现场网络与跳转记录。

官方依据：

- 页面：`https://wisdom-mooc.zhihuishu.com/study/index`
- 学习组件：`https://wisdom-mooc.zhihuishu.com/assets/index-QJOUvpDU.js`
- 读取日期：2026-11-13；通过本地 HTTP 请求按原始字节读取，无需登录或打开 F12。
- 原始响应：1,061,290 字节；SHA-256：`2eadbe0f6c66edf25c9f5c9f60afa3e7d3a8f57cb941da8bda57494a2793d59c`。
- 定位点：`Ee` 注册播放器点击检查；`ve` 处理异常并跳转首页；`gn` 检查目录切换事件。

## 本次修改

- 智慧树学习页取消程序切课点击及宽泛的“下一节”节点查询，避免触发已确认的点击检查，也不再误点其他同名链接。
- 视频自然结束后继续等待网站成功保存学习记录；确认后显示“等待手动切课”，请用户点击网站的“下一节”或课程目录。
- 手动切课或网站自身切换后，仍按新视频源重建状态并自动续播；新视频需要自己的保存回执，旧回执不会把新课标记为已保存。
- 设置改为“完成后提醒手动切课”。旧“完成后自动下一视频”的布尔值自动迁移，模型设置、Key 存储键、安装名称与 namespace 保留。
- 提醒关闭时显示“播放完成”，仍可手动选择下一课。控件缺失或禁用不再被当作整个课程完成的证据。
- AI 随堂练习识别、填选核对、提交回执确认和继续学习保留；北部湾、超星及智慧树旧考试页沿用原逻辑。

本次没有修改网站的事件真实性检查、异常处理或跳转，也没有生成可信点击或伪造学习记录。智慧树学习页不再承诺无人值守自动切课。

## 验证

- 先复现：新增真实点击检查场景在旧控制器下失败，其余 37 项浏览器场景通过。
- 配置迁移测试先失败，补齐迁移并重新构建后通过；原开关值及模型配置不变。
- Node 回归：31/31 通过，包含设置迁移、回执观察、请求协调和旧适配回归。
- 浏览器回归：40/40 通过，源码控制器与最终分发控制器各运行同组场景。模型答案、媒体状态和网站回执均为隔离模拟；不是 80 个独立场景。
- 完整分发脚本隔离启动：版本 `0.2.9.13`；保存前显示“等待网站确认”，模拟成功回执后显示“等待手动切课”；播放器点击 0 次、误提交 0 次、运行异常 0 个。
- 构建、完整脚本语法、元数据一致性、重复构建逐字一致、密钥模式扫描、校验和及 diff 检查通过；结果记录于 `verification/verification-0.2.9.13.json`。

未完成用户真实登录课堂验收，无法访问用户外部 Edge 的登录状态。上述模拟通过不等于用户账号的现场验收，也不能保证网站今后不改变规则或不触发其他验证。

## 更新与使用

1. 在暴力猴／油猴的原脚本条目点击“检查更新”，确认版本 `0.2.9.13`，刷新课堂。同一浏览器只启用一份本脚本。
2. 视频结束后等待面板确认学习记录已保存，再亲自点击网站“下一节”或目录。新视频加载后助手按原设置自动续播。
3. 如果手动点击仍返回首页，先暂停助手，记录是否有网站提示，并使用“个性化设置 → 复制诊断”反馈脱敏内容。验证码、身份验证和重新登录仍由用户处理。
